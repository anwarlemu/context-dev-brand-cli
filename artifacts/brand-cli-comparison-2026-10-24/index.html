ENGINEERING AUDIT · 24 OCTOBER 2026 · SHADCN 4.22.1 → BRAND CLI 2.1.0 CANDIDATES

The main gap was installation and agent workflow consistency.

Published versions of Context, Inkbox, Agentcard and OpenCommerce were installed and tested against shadcn. Their existing components were generally usable, but project configuration, JavaScript output, safe conversion, discovery and ecosystem integration were uneven. Those reproduced gaps now have fixes and regression coverage across all four repositories.

Delivery status: these are local 2.1.0 candidates. This audit has not pushed branches, published packages or deployed the sites. The new hosted registry addresses become usable after deployment. Pre-existing local commits in the repositories were preserved.

What changed

  • Consistent info → search → view → add --dry-run → add workflow, with JSON output and project targeting.
  • Configured aliases, inherited JSONC configs, JSX/JS output, custom paths, exact diffs, overwrite control and idempotent installs.
  • Separate brand utilities preserve existing app helpers. Dependency failures occur before component files are changed.
  • Conversion preserves custom labels, behavior and unrelated color data. Referenced TypeScript projects are checked before accepting adaptations.
  • Portable agent skills are installed by init and add. Standard registries enable the actual upstream MCP and workspace implementation.
  • Theme/font conflicts were corrected, and missing utility aliases added without changing the brands' component designs.

Agent handoff

Use the installed CLI with this task contract. The shipped skill contains the same concise workflow and links to the longer brand guide. A normal agent does not need to memorize component variants or infer install paths.

Use this project's brand design system.
Run npx <brand-ds> info --json.
Find components with search, then read view <names> --json.
Preview add <names> --dry-run --json, then install.
Read the installed source for exact variants, props and callback signatures.
Preserve existing content, state and event handlers.
Run the app build, keyboard checks and desktop/mobile verification.
Use apply only for an explicitly requested restyle.

For direct upstream installation after brand init: npx <brand-ds> shadcn add @<brand-ds>/theme @<brand-ds>/button. The explicit theme updates existing aliases. Native add applies the theme automatically.

Rendered installation fixtures

These are small integration fixtures, not proposed product layouts. Tests cover button callbacks, input values, dialog Escape/focus return, mobile overflow, expected theme values and preservation of an artwork color. External font requests were blocked for deterministic tests; font-family declarations were verified, not font CDN availability.

Coverage limits and remaining differences

  • No numerical claim of Claude/Codex task success is made. Structured discovery, portable skills and real MCP calls were tested; independent model evaluation and host activation were not.
  • React/Tailwind prerequisites and brand component APIs remain intentional constraints. Upstream base/preset/RTL flags do not automatically make branded components compatible with another primitive API.
  • Vite, a shared UI workspace and all four Next documentation sites were built. Every framework template, package manager, operating system, dark-mode permutation, interaction frequency and assistive technology combination was not exercised.
  • Hosted registries and sites require release/deployment. Distribution remains through GitHub release branches; npm publication was not performed.
  • The legacy bare command still starts conversion. New guidance uses explicit discovery/setup/apply commands. A future breaking release can remove the old ambiguity.
  • The four repositories still carry their engines separately. Identical workflow regression suites now protect the shared behavior, but source consolidation is a separate architectural change.
